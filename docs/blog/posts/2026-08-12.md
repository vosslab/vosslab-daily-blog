# Making the Teaching Loop Explicit

Today I focused on making educational software behave less like a collection of inherited exceptions and more like a clear, repeatable teaching system. In [Peptidyle Learning Engine](https://github.com/vosslab/peptidyle-learning-engine), that meant retiring old compatibility paths, exposing the inputs to a real walkthrough, and protecting the boundary between author tools and the student experience.

<!-- more -->

## Making the normal path visible

Peptidyle is a mastery-learning platform: students work through fresh versions of problems until they can solve them reliably, while grading and answer keys stay securely on the server. The basic idea is simple. Keeping that experience dependable as a project grows is harder.

I removed an early flat-question format that was still lingering underneath the current content system. It had readers, converters, test fixtures, and private branches built around a pre-production design. Leaving that scaffolding in place would have meant that "current" content still depended on an obsolete interpretation before the platform could use it.

The replacement is a native path for the current version of flat content. That is not a flashy feature, but it makes the authoring model easier to explain and maintain: authors create content for the system that actually exists, rather than for a compatibility layer that happens to translate it.

I made the same choice in the user-interface walkthrough. Previously, part of its behavior depended on hidden environment settings. I replaced those with documented command-line choices and one explicit, versioned private input file. A demonstration is more useful when another person can see what it needs, change it deliberately, and reproduce it without remembering undocumented launch rituals.

## Keeping the student view honest

I also expanded the protected authoring surface across all eight current question families. That gives instructors a broader way to build and inspect content while preserving an important limit: accepted answers and feedback remain outside the learner-equivalent preview.

That distinction matters. It would be convenient to show everything in one place, but a preview that exposes answer-key material is no longer a credible approximation of what students see. I want the authoring experience to be capable without quietly changing the educational boundary it is meant to inspect.

I accepted the day's human-guidance workflow only after rerunning it from its real starting conditions. Completed plan checkboxes are not enough evidence that a teaching loop works. I verified the visible four-stage flow on a clean stack without email dependencies, because "implemented" and "demonstrated in a clean environment" are different claims.

I also simplified the learner and instructor pages. They now read more like compact academic workspaces than piles of padded panels. The visual change is restrained-a narrow color rail carries course identity-but it gives the content and next action more room to be found quickly.

## Building for contributors, too

A broad Rust validation run revealed a practical problem: the build directory grew to 136 GB. I changed the shared development settings to stop using incremental compilation while keeping enough debugging information to investigate failures. Rebuilds may take longer, but a workflow that quietly consumes unreasonable storage is not a sustainable contributor experience.

The day included two useful reminders from other projects. In [Super Bowling](https://github.com/vosslab/super-bowling), I corrected the live camera for very dense racks by anchoring it to the first confirmed ball-pin collision instead of continually reframing the entire field of pins.


That choice keeps the important moment-the ball's approach and first impact-legible even when hundreds of pins are on screen. I kept the existing rendering path after comparison testing showed that the suspected issue was repeated pin-body composition, not missing pins. Some larger cascade behavior remains an evidence blocker rather than something I am treating as finished.

In [Ferrum Chemical Forge](https://github.com/vosslab/ferrum-chemical-forge), I also completed a deliberately narrow bridge to a native chemistry library for one operation: assigning alternating bond patterns in molecular structures. I kept the interface small, versioned, and explicit about ownership. The public header is now the single authority for the numeric values shared across the language boundary, reducing the risk of two sides that compile successfully but silently disagree.

Across all three efforts, the theme was the same: remove implied behavior, name the boundaries, and verify the path people will actually use.
