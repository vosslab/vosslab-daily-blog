# Cutting the Installer Down to Size
<!-- more -->

Today's most useful work was not adding another capability; it was deciding which capabilities should not exist. In [vosslab-skills](https://github.com/vosslab/vosslab-skills), I rebuilt the installer around a simpler premise: the repository is authoritative, and an installed copy is disposable. That turned a growing state-management project back into an installer.
## Letting the repository be the source of truth

vosslab-skills is the shared catalog of skills and agent roles I use across Claude, Codex, Cursor, and OpenCode. It had accumulated the sort of machinery that seems prudent while designing an installer: profiles, receipts, ownership hashes, version comparison, pruning, status reports, backups, and multiple command modes.

The surprise was that none of it was solving a problem the project actually had. The installer does not need to reconcile two equal authorities. The Git checkout is current; target directories are stale projections. Once I accepted that, the design got much cleaner.

The main `install_skills.py` command is now a guided interview from the repository root. It shows declared destinations, asks for final approval, and writes only the requested platform entries. Matching entries remain untouched; mismatches are replaced from Git. Source-backed skills and authored agents are symlinked instead of copied, so the installed view stays live with the checkout. Only platform-native projections that have no authored target-format source become regular generated files.

That decision also removed an alternate-home question. Normal installations should target the operating system's current home, full stop. The end-to-end test can provide a temporary `HOME`; the human-facing installer does not need to turn that test seam into product surface area.

The useful surprise was how much architecture disappeared once "installed directories are stale" became a design fact. A six-pass audit made the corresponding KISS rule explicit: hypothetical duplicate names do not justify a collision-management framework when the current catalog has no collisions.

## Making categories describe themselves

The other substantial rewrite was discovery. I renamed abbreviated public category directories and moved category discovery, validation, and index generation to direct `CATEGORY.md` metadata rather than a centrally maintained roster. The catalog can now explain itself closer to where its content lives.

This sounds like an organizational cleanup, but it changes how the project fails. A forgotten roster entry is a silent drift problem. Metadata beside the category makes the category itself the unit that discovery validates. The installer's Codex target now links canonical categories once, while Claude remains flat under `skills`; Cursor and OpenCode use their respective native roots.

The release gate passed 3,708 tests, an isolated temporary-home primary E2E, generated-output checks, and the OpenAI-sidecar contract check. There is one deliberately unresolved concern: some propagation-owned `tests/test_*.py` files were locally changed during the discovery migration. The audit identified that as a durability risk. It needs either an upstream template change or a compatible local boundary; "all tests pass" is not the same as "future propagation will preserve this."

## Authority work in the learning engine

In [Peptidyle](https://github.com/vosslab/peptidyle-learning-engine), the day was more about making teaching operations trustworthy than making them flashy. The teaching-operations slice settled several authority boundaries: course-group policies are purpose-specific, deleting a referenced group refuses cleanly, co-instructor invitations are target-bound and expire after 30 days, and removing the final active Instructor is forbidden.

The interesting part is the atomic re-evaluation of active work after membership, audience, purpose, or modifier changes. It is easy to treat those as separate settings; it is harder, and more correct, to treat them as changes that can invalidate the meaning of already-active learner work while preserving sealed receipt history.

I also repaired the local stack so ordinary starts replace project containers instead of accumulating them. Two consecutive starts replaced all nine containers without increasing container, image, or volume counts. Infrastructure lifecycle behavior is part of correctness here, not housekeeping.

## Smaller modules, smaller claims

[qti-package-maker](https://github.com/vosslab/qti-package-maker) got a quieter version of the same treatment. Its Blackboard ZIP reader was split into package orchestration, media recovery, and item-XML parsing without changing `read_items_from_file()`. That preserves the public seam instructors and integrations rely on while making the awkward HTML repair behavior live beside the parser that owns it.

Meanwhile, [Ferrum](https://github.com/vosslab/ferrum-chemical-forge) narrowed attached-cyclohexane insertion to a private deferred-ID capability rather than a generic attachment framework. Five atom IDs and six bond IDs are reserved only in copied sequences, fenced by revision, digest, session, and one-use commit rules, then committed as one history transition.

The important discovery there was architectural, not chemical. A source-level negative result showed that the broad plan was reaching for an unowned duplicate geometry. The replacement split the work cleanly: a private pure C6 pose and anchor-admission probe first, then a concrete `PendingAttachedCyclohexaneV1` capability with revision, digest, session, anchor, and one-use fencing. Sequential commits, live preallocation, generic attachment APIs, and serialized receipts all stayed rejected.

The day ended with small infrastructure follow-through. A universal `.graphifyignore` in [starter-repo-template](https://github.com/vosslab/starter-repo-template) now omits tests, development material, tools, and documentation from repository maps while preserving project-specific additions. The thread across all of it was simple: keep the useful capability, make its owner explicit, and refuse to build a platform around a case that has not earned one.
